\subsection{Planned v0.4.1: Corrected Radio Model}
v0.4.1 replaces the i.i.d. SINR abstraction with a received-power model aligned with
\cite{gomez2018stochastic}.
\begin{itemize}
    \item \textbf{Received power}: for user at $x$ and satellite at $y$,
    $P(x,y)=P_t G_{xy}\|x-y\|^{-\gamma}$, where $\gamma$ is the path-loss exponent and
    $G_{xy}\sim \mathrm{Exp}(1)$ models Rayleigh fading.
    \item \textbf{Serving satellite}: $y_0=\arg\max_y P(x,y)$ among visible satellites.
    \item \textbf{SIR}: $\mathrm{SIR}(x)=\frac{P(x,y_0)}{\sum_{y\in \Phi_b} P(x,y)-P(x,y_0)}$.
    \item \textbf{SINR}: $\mathrm{SINR}(x)=\frac{P(x,y_0)}{\sum_{y\in \Phi_b} P(x,y)-P(x,y_0)+N_0 W}$.
    \item \textbf{Capacity}: $C=W\log_2(1+\mathrm{SINR})$ drives throughput metrics.
\end{itemize}
Definitions: $P_t$ is per-satellite transmit power (W); $G_{xy}$ is a unitless small-scale
fading power gain for the link $x\leftrightarrow y$ (fast fading from multipath, modelled as
exponential with mean 1 under Rayleigh fading; power exceeds its mean about 37\% of the time);
$\|x-y\|$ is link distance (m) measured in 3D;
$\gamma$ is the path-loss exponent; $\Phi_b$ is the set of visible satellites for user $x$;
$y_0=\arg\max_y P(x,y)$ means the user associates to the visible satellite with the highest
instantaneous received power (strongest link, with ties broken arbitrarily); $N_0$ is noise
spectral density (W/Hz); $W$ is link bandwidth (Hz). SIR ignores noise, SINR includes noise.

In this model the fast multipath fluctuations are captured by a random “fading power gain” ($G_{xy}$) 
that multiplies received power, and under Rayleigh fading ($G_{xy}\sim \mathrm{Exp}(1)$) 
(an exponential with mean 1), so the link power randomly rises above or below its average due to 
constructive/destructive interference.

\subsection{Planned v0.4.2: Outage Experiment and Test Harness}
v0.4.2 sets up the outage experiment and test harness without changing simulator behaviour.
\begin{itemize}
    \item \textbf{Outage definition}: for a trial with user set $\mathcal{U}$ and per-user service indicators
    $S_i \in \{0,1\}$, define outage rate as
    $o = 1 - \frac{1}{|\mathcal{U}|} \sum_{i \in \mathcal{U}} S_i$.
    The simulator defines $S_i$ (default: user is visible and throughput $\ge R_{\min}$).
    \item \textbf{Bernoulli experiment}: define the success event $A=1$ iff $o \le o_{\max}$.
    For a design $d$, estimate $p = \mathbb{P}(A=1)$ and certify feasibility when
    $\mathrm{LCB}(p) \ge p_{\mathrm{target}}$ using existing Bernoulli certificates.
    \item \textbf{Trial validity}: ignore trials with $|\mathcal{U}|=0$ (no ground demand).
    \item \textbf{Simulator contract}: require \texttt{outage\_rate} and \texttt{n\_ground} metrics
    from the adapter, even before PRBs are implemented.
\end{itemize}

\subsection{Planned v0.5: PRB Capacity and Outage Results}
v0.5 is split into subversions to manage PRB complexity while producing outage results.
\begin{itemize}
    \item \textbf{v0.5.1}: add the satellite PRB grid and PRB demand mapping, leaving allocation policy minimal.
    \item \textbf{v0.5.2}: introduce a configurable scheduler and derive throughput from allocated PRBs.
    \item \textbf{v0.5.3}: compute outage from SINR and PRB availability and report certified dimensioning outputs.
\end{itemize}

\section{Appendix: Delivered Product Specifications}

\subsection{v0.3: QoS and Channel Quality}
QoS is defined by two minimum constraints that must both be met:
\begin{itemize}
    \item \textbf{Coverage}: at least $C_{\min}$ fraction of users in the latitude band are served (exact definition of
    ``served'' to be specified by the simulator model).
    \item \textbf{Throughput}: at least $R_{\min}$ throughput is delivered (exact definition to be specified; expected to be
    driven by a simple SINR-based capacity model).
\end{itemize}

\subsubsection{Discussion: Signal Quality and QoS Considerations}
\begin{itemize}
    \item Channel quality is defined as SINR with a lognormal model:
    $10 \log_{10}(\mathrm{SINR}) \sim \mathcal{N}(\mu_{\mathrm{dB}}, \sigma_{\mathrm{dB}}^2)$, i.i.d. per link.
    \item Signal quality may degrade with Doppler and path length; these are known if the ephemeris is known.
    \item Angular velocity adds Doppler shift which degrades signal
    \item Channel capacity model: $C = W \log(1 + \mathrm{SINR})$ with $\mathrm{SINR} = S / (I + N)$.
    \item QoS may be expressed as $\mathbb{P}(C \ge C_{\min})$ being sufficiently high.
    \item With higher channel capacity, fewer resources are required; PRB mapping can be added later.
    \item Erlang-style traffic models may be relevant for network blocking and load.
    \item \textbf{Latency}: max 300 ms.
    \item \textbf{KPIs / QoS}: consider explicit resource allocation to users based on the above.
\end{itemize}
To preserve plug-and-play separation, v0.3 introduced a global simulator configuration passed from the orchestrator to
the simulator only. Experiments, certificates, orchestration logic, and optimisers remain unchanged and consume only
aggregated metrics. The simulator config is responsible for selecting and parameterising channel-quality models, demand
generators, and allocation policies, and for defining the output throughput metric used by the experiment.
Coverage and throughput functions must be configurable plugins so alternative definitions can be swapped without
changing experiment or certificate code.
\begin{itemize}
    \item \textbf{v0.3.1}: define and validate the adapter boundary and simulator config contract.
    \item \textbf{v0.3.2}: introduce lognormal SINR channel-quality modelling and add simulator-level tests.
    \item \textbf{v0.3.3}: add an end-to-end coverage + throughput dimensioning test.
\end{itemize}

\subsubsection{v0.3.1: Adapter Boundary and Config Contract}
The adapter boundary formalises how the orchestrator interacts with a simulator backend.
\begin{itemize}
    \item \textbf{Orchestrator input}: a validated \texttt{SimulationConfig} object (serialisable to JSON/YAML) that
    selects plugin implementations and provides their parameters.
    \item \textbf{Simulator input}: backend-specific configuration derived from \texttt{SimulationConfig}
    (e.g., config files, CLI flags, or API payloads).
    \item \textbf{Simulator output}: a metrics dictionary with keys required by the experiment (e.g., \texttt{coverage},
    later \texttt{throughput}).
    \item \textbf{Determinism}: all per-trial randomness must be controlled by a trial seed supplied by the orchestrator,
    ensuring repeatable trials for certification.
    \item \textbf{Errors}: adapter must surface clear, typed errors for configuration validation, execution failures, and
    output parsing issues.
\end{itemize}

\subsubsection{v0.3.2: Lognormal SINR Channel Quality}
v0.3.2 introduced a minimal, standard channel-quality model while keeping the math tractable.
\begin{itemize}
    \item \textbf{Channel quality definition}: per-link SINR with $10 \log_{10}(\mathrm{SINR})
    \sim \mathcal{N}(\mu_{\mathrm{dB}}, \sigma_{\mathrm{dB}}^2)$, i.i.d. across links.
    \item \textbf{dB convention}: SINR is a linear power ratio; its dB form is
    $\mathrm{SINR}_{\mathrm{dB}} = 10 \log_{10}(\mathrm{SINR})$ with $10 \log_{10}(P_2 / P_1)$ for power ratios.
    \item \textbf{Config}: add a channel-quality block to \texttt{SimulationConfig} with parameters
    $\mu_{\mathrm{dB}}$, $\sigma_{\mathrm{dB}}$, bandwidth $W$, and a throughput aggregation rule.
    \item \textbf{Throughput mapping}: default throughput uses $C = W \log(1 + \mathrm{SINR})$ on the
    selected link per user (e.g., best visible SINR), with the aggregation rule configurable.
    The default aggregation is mean throughput across users (not a percentile such as p10).
    \item \textbf{Experiment and certificate}: add a throughput-aware Bernoulli experiment that
    declares success when both coverage and throughput constraints are met, certified with the
    existing Bernoulli confidence bounds.
    \item \textbf{Scope}: no PRB modelling or spatial correlation in v0.3.2; those remain optional extensions.
\end{itemize}

\subsubsection{v0.3.3: Throughput-Aware Dimensioning}
v0.3.3 integrates throughput into the dimensioning loop and certification workflow.
\begin{itemize}
    \item \textbf{End-to-end dimensioning}: run the search loop with the throughput-aware QoS experiment
    and Bernoulli certificate, returning the minimum design that satisfies both coverage and throughput targets.
    \item \textbf{Targets}: define $C_{\min}$ and $R_{\min}$ per run; certify feasibility using existing confidence
    bounds (no new certificate type required).
    \item \textbf{Outputs}: report the certified design and include coverage and throughput metrics used for acceptance.
\end{itemize}

\subsection{v0.2 Delivered Product Specification}
\subsubsection{Purpose}
Provide a dimensioning decision for a LEO satellite operator: the minimum number of satellites required to meet
operator-defined coverage targets, under priors on user demand and satellite distributions.

\subsubsection{Users}
Day-to-day users are LEO satellite operators who own and operate satellite constellations.

\subsubsection{Decision and Optimisation Target}
The product outputs a recommended minimum constellation size $N$ such that coverage targets are satisfied with high
probability. The optimisation objective is coverage feasibility (not cost, routing, or detailed PHY performance).
The design variable is the satellite Poisson mean (intensity), reported as the recommended $N$.

\subsubsection{Geographic Usage Zones}
The operator specifies a single latitude band:
$$
[\mathrm{lat}_{\min}, \mathrm{lat}_{\max}], \quad \mathrm{lat}_{\min} \le \mathrm{lat}_{\max}.
$$
Users are drawn only from within this band on a spherical Earth model.

\subsubsection{Modelling Assumptions}
\begin{itemize}
    \item \textbf{Users}: sampled as a Poisson point process (PPP) on the spherical Earth surface, restricted to the latitude
    band.
    \item \textbf{Satellites}: sampled as a PPP on a spherical orbital shell. Sampling is gated by a maximum off-nadir
    visibility angle from the extremal latitude bounds (i.e., only satellites that could be visible from the band edges
    are considered).
    \item \textbf{Coverage}: evaluated per user by considering only satellites within that user's visibility constraint,
    with an explicit horizon gate to exclude satellites below line of sight.
\end{itemize}

\subsubsection{Inputs}
\begin{itemize}
    \item Latitude band $[\mathrm{lat}_{\min}, \mathrm{lat}_{\max}]$.
    \item Poisson mean (intensity) for the ground user distribution (input prior).
    \item Altitude for the satellite orbital shell.
    \item Maximum off-nadir angle for visibility gating.
    \item Coverage target $C_{\min}$ for the latitude band.
    \item Certification parameters: confidence level $1-\alpha$ and feasibility target $p_{\mathrm{target}}$.
\end{itemize}

\subsubsection{Outputs}
\begin{itemize}
    \item Recommended minimum constellation size $N$.
    \item Certificate: a confidence-backed lower bound on $\mathbb{P}(\text{coverage target met})$ under the stated priors.
    \item Reproducibility artifact: simulator configuration and seeds sufficient to replay the certification run.
\end{itemize}

\subsubsection{Statistical Certification}
Define a Bernoulli per-trial success event $A$ where $A=1$ iff the coverage target is met in that trial.
Let $p := \mathbb{P}(A=1)$ under the stated priors and simulator configuration.
The product certifies feasibility by returning, with confidence $1-\alpha$, a lower confidence bound $\mathrm{LCB}(p)$ and
declaring the design feasible if $\mathrm{LCB}(p) \ge p_{\mathrm{target}}$.

\subsubsection{Scope and Non-Goals}
\begin{itemize}
    \item \textbf{In scope}: Poisson-based coverage dimensioning on a 3D spherical Earth model with certification and
    closed-form assumptions.
    \item \textbf{Out of scope (v0.2)}: QoS/throughput constraints and PRB capacity modelling; ephemeris-driven orbital
    planes; detailed PHY/link-budget simulation; full network routing; end-to-end application performance.
\end{itemize}

\subsubsection{Implementation Notes}
v0.2 was achieved by updating the simulation layer only (3D spherical PPP coverage with horizon and off-nadir gating).
Experiment semantics, certificates, orchestration, and optimisation layers were reused without modification.
\newline\textbf{Poisson sampling}: implementations must use a numerically stable Poisson sampler for large intensities
(e.g., NumPy's \texttt{poisson}) to avoid underflow and saturation in high-$\lambda$ regimes.


\subsection{v0.1 Delivered Product Summary}
Version 0.1 delivered a certified dimensioning capability for LEO operators focused on coverage feasibility under
stochastic user and satellite distributions. The product produced a minimum constellation size $N$ satisfying coverage
constraints with statistical certification, using a simplified world simulator and Monte Carlo trials. While a 2D circular world
was used for testing, the framework and certification method were already suitable for extension to a 3D spherical world. 

In v0.1, both ground stations and satellites were modelled as Poisson point processes, with the design variable being
the satellite Poisson mean. A trial sampled Poisson counts, placed points, computed a coverage fraction, and
declared success if coverage met a target. The certificate reported a lower confidence bound on the true success
probability based on multiple seeded simulations, and the solution was the minimum Poisson mean whose bound met the target confidence level.

Throughput modelling via PRB capacity, detailed physical layer / link budgets, and full network routing were not part of v0.1 scope.
